# SentinelCore — Runtime Security Review

Evidence-based review of the release stack's runtime posture. Sources: the
release compose (`build/overlay/templates/docker-compose.release.yml`), the
product Dockerfiles (read-only), the installer, and the relay tests.

## 1. Containers run as non-root
| Service | User | Caps | Notes |
|---|---|---|---|
| backend | `appuser` (uid 1000) | `cap_drop: ALL`, `no-new-privileges` | app Dockerfile `USER appuser`; release cmd drops `--reload` |
| worker | `appuser` | `cap_drop: ALL`, `no-new-privileges` | same image as backend |
| helper | root (inside) | `cap_drop: ALL` + `NET_ADMIN,NET_RAW,SYS_NICE,CHOWN` only | **never** `privileged: true`; this is the sole privilege boundary |
| db | postgres | default | loopback host port only |
| redis | redis | default | no host port |
| nginx | nginx | default | only published port (:80) |
| relay-shim | `shim` (uid 1000) | default | in-stack only, aliased to api.brevo.com |

**Verdict:** PASS. Only `helper` holds capabilities, scoped to four, and it is
reachable solely via the `0660 root:sentinelcore` Unix socket (GID 2000 match).

## 2. No unnecessary capabilities / privilege
- backend/worker: `cap_drop: ALL` + `security_opt: no-new-privileges:true`.
- helper: minimal allowlist; host networking grants *visibility*, not reachability
  (publishes no port).
- **Verdict:** PASS.

## 3. Services bound to localhost by default
- `nginx` publishes `80:80`; the installer defaults bind address to `127.0.0.1`
  and **warns** if the operator chooses `0.0.0.0`.
- `db` publishes `127.0.0.1:5433` only (loopback).
- redis, backend, worker, helper, relay-shim publish **no** host ports.
- **Verdict:** PASS (with operator opt-in required to expose beyond localhost).

## 4. RBAC
- Roles: Admin, Analyst (`UserRole` in the app). First admin seeded by the app's
  own `scripts.seed_admin` at install.
- Auth hardening (from source, unchanged): Argon2 hashing, short-lived access
  tokens, refresh cookie scoped to `/api/auth` and `Secure` in production, login
  throttling per username+IP (Redis).
- **API smoke test (to run on a live stack / VM step 5):** unauthenticated access
  to protected endpoints → 401; admin-only endpoints reject analyst tokens.
- **Verdict:** design PASS; live assertion is VM step 5.

## 5. Default credentials absent
- No shipped password: installer generates DB/JWT/webhook secrets; admin password
  is either operator-chosen (≥12, mixed classes) or app-generated once.
- `SECRET_KEY` is always generated — the dev placeholder (`dev-only-placeholder…`)
  is never shipped (audit greps for it).
- **Verdict:** PASS (audit enforces: `tests/run-all.sh` → audit).

## 6. HTTP security headers
- Website: `public/_headers` sets CSP, X-Content-Type-Options, Referrer-Policy,
  X-Frame-Options, Permissions-Policy, HSTS.
- App API: served behind nginx; `X-Forwarded-*` set. (App-level headers are the
  source app's responsibility; the release does not weaken them.)
- **Verdict:** website PASS; app headers unchanged from source.

## 7. Relay security
Covered by automated tests (`relay/tests/`, 10 passing):
- **auth**: token hashing (SHA-256, only hashes stored), bearer parsing, admin-secret
  constant-time compare. (`test_auth.py`)
- **rate-limit + quota**: sliding window + DB-backed daily counters. (`test_quota.py`)
- **template allowlist**: strict `E##` ids; HTML escaping. (`test_templates.py`)
- **e2e**: register → verify → send via shim → revoke → send rejected; recipient
  restricted to the install's admin; pre-verification send refused; admin endpoints
  require the admin secret. (`test_e2e.py`)
- **Verdict:** PASS.

## 8. TLS / egress note (carry-forward decision)
- The shim presents an install-local cert for `api.brevo.com`; backend trusts it
  via `SSL_CERT_FILE` (CA generated by `installer/lib/tls.sh`). The relay↔provider
  hop uses real TLS with `verify=True`.
- Front-door TLS for the UI (`:80`) is still an **owner decision** (see
  `docs-internal/gaps-and-risks.md` item 12): `ENVIRONMENT=production` marks the
  refresh cookie `Secure`, which needs HTTPS in front.
- **Verdict:** OPEN — owner decision required before exposing beyond localhost.

## Residual risks / open items
1. Front-door TLS story for a production-flagged box (gaps item 12).
2. Suricata ruleset source — bundled vs. `suricata-update` (gaps item 6).
3. shellcheck + bats not run on the authoring host — run in CI/on target (below).
4. Docker image filesystem/history scan not run here (no Docker) — the audit does
   it automatically on the build host.
