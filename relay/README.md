# SentinelCore Email Relay

A small FastAPI service the **owner** runs so that real email-provider
credentials never ship to customer boxes. Each install registers once, verifies
its admin email, and receives a revocable, rate-limited, per-install bearer
token. The relay holds the only provider key and sends on the install's behalf.

## Why
Anything on a customer PC can be extracted. The provider key lives ONLY here.
A leaked install token is revocable, capped, and can mail only that install's
verified admin address.

## Endpoints
| Method | Path | Auth | Purpose |
|---|---|---|---|
| POST | `/v1/register` | per-IP rate limit | `{admin_email, install_id, version}` → `{token, from_name, sender_address}`; emails a verification link; token inactive until verified. |
| POST | `/v1/verify` | — | `{install_id, code}` → activates the token. (The emailed link is `GET /v1/verify?install_id&code`.) |
| POST | `/v1/send` | Bearer token | `{template_id, variables, to?}` — renders an **approved** template server-side (no arbitrary HTML). Recipient must be the install's verified admin. |
| POST | `/v1/send_rendered` | Bearer token | Used by the Brevo shim for the unmodified app: `{to, subject, text, html, tag}`. Same auth/quota/recipient gating + size cap + `E##` tag allowlist. |
| POST | `/v1/revoke` | `X-Admin-Secret` | `{install_id}` → revoke. |
| GET | `/v1/admin/installs` | `X-Admin-Secret` | List installs (hashes only, send counts). |
| GET | `/v1/health`, `/healthz` | — | Liveness. |

## Security properties
- Only token **hashes** are stored (SHA-256); plaintext token returned once.
- Per-IP registration limit, per-token send rate limit, per-token + global daily
  quotas (DB-backed), request size cap.
- Recipients restricted to the install's verified admin email.
- Template allowlist: strict ids on `/v1/send`; `E##` tag allowlist on the shim path.
- Structured logs carry metadata only — never bodies, never tokens, never the
  provider key.

## Provider adapters (`app/providers/`)
`RELAY_PROVIDER` selects the adapter (`fake` for dev/tests, `brevo` for prod).
Switching providers is a config change on the server; credentials come from the
server env only. Add a provider by implementing `Provider.send()` in a new
module and wiring it in `providers/__init__.py`.

## The app-side shim (`shim/`)
The unmodified SentinelCore backend POSTs to `https://api.brevo.com/v3/smtp/email`.
In the release stack that host name is a network alias for the `relay-shim`
sidecar, which reads the per-install token from the `api-key` header, extracts
the `E##` type from `tags`, and forwards to `/v1/send_rendered`. The shim
presents an install-local cert for `api.brevo.com` (generated by the installer),
so the backend's `verify=True` egress is satisfied with no source edit.

## Run locally
```bash
python -m venv .venv && . .venv/bin/activate   # Windows: .venv\Scripts\activate
pip install -r requirements.txt
RELAY_PROVIDER=fake RELAY_ADMIN_SECRET=dev uvicorn app.main:app --port 8080
```

## Tests
```bash
PYTHONPATH=. pytest -q      # auth, quota, template allowlist, and full e2e
```
The e2e covers: register → verify → send template mail via the shim → revoke →
send rejected, using the fake provider in-process (no network).

## Install-side config
The install's relay base URL comes from one product-level value, `RELAY_URL`
(`installer/lib/product.sh`), so repointing future builds is a one-line change.
